# Secrets/KMS Operational Policy

## Production policy
- `BONIFACIY_SECRET_BACKEND=fernet`
- `BONIFACIY_SECRET_KEY` must be generated by secure process and stored in secret manager.
- `BONIFACIY_API_SIGNING_KEY` must be separate from encryption key.
- `insecure-xor` is forbidden in production.

## Rotation
1. Generate new encryption key in secret manager.
2. Generate new API signing key:
   ```bash
   python main.py generate-signing-key
   ```
3. Deploy new app revision with dual-read/single-write migration window.
4. Re-encrypt stored credentials.
5. Revoke old key and rotate API signing key references in secret manager.
6. Revoke active API sessions:
   ```bash
   # revoke all sessions
   python main.py revoke-sessions

   # revoke sessions for specific user
   python main.py revoke-sessions --user-id <id>
   ```
7. Audit login/session anomalies.

Helper script (optional):
```bash
./scripts/security_incident_rotate.sh            # revoke all sessions
./scripts/security_incident_rotate.sh <user_id>  # revoke one user
```

## Emergency recovery
- Keep encrypted backup of key material in offline escrow.
- Recovery requires two-person approval.
- After recovery, force immediate key rotation and session revocation.
